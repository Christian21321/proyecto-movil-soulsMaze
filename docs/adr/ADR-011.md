# ADR-011: Interfaz de usuario Jetpack Compose (Etapa 6)

## Contexto

CardClash necesita una interfaz de usuario para: menu/navegacion, coleccion de
cartas y progresion del jugador, historial de partidas y el combate PvP por
turnos.

La logica de dominio (motor, progresion), la persistencia local (Room) y la
capa remota (Firestore) ya existian. La UI debia consumirlos siguiendo el patron
MVVM + StateFlow + UDF definido en ADR-006, manteniendo el dominio puro y el
acoplamiento a Android confinado a la capa UI.

No existia configuracion Compose previa (MainActivity era un placeholder
`AppCompatActivity`).

## Opciones consideradas

- **Views XML / AppCompat tradicional**: se descarto por la arquitectura
  declarativa exigida por ADR-006 y la productividad de Compose.
- **Kotlin View/Anko, Flutter, React Native**: fuera del stack Android/Kotlin
  del proyecto; se mantiene Compose.
- **Hilt/Dagger para DI**: se descarto en favor de un `AppContainer`/
  ServiceLocator sencillo (coherente con la DI manual del ADR-002), suficiente
  para el alcance.
- **Pantalla de combate solo-minima (Opcion B)**: se eligio la **Opcion A**
  (esqueleto completo de combate con logica pura testeable y gateway integrado),
  verificable hoy mediante el modo local demo.

## Decision

Se adopta **Jetpack Compose con Material 3** como framework de UI de la Etapa
6, con arquitectura MVVM/UDF y Navigation Compose para la navegacion.

### Toolchain

Compose BOM 2026.08.00 (UI 1.12.0, Material3 1.4.0), activity-compose 1.13.0,
lifecycle 2.9.4, navigation-compose 2.9.8, plugin
`org.jetbrains.kotlin.plugin.compose` 2.2.10 (coincide con la KGP embebida
de AGP 9.3.2; NO se usa `org.jetbrains.kotlin.android`, deprecado en AGP 9).
`buildFeatures.compose = true`; `composeOptions.kotlinCompilerExtensionVersion`
NO se declara (deprecado/ignorado en AGP 9). Kotlin embebido + JDK 25.

### Estructura de paquetes (`com.cardclash.ui`)

- `theme/`: Material3 `CardClashTheme`, dark/light, marca violeta/dorado.
- `navigation/`: Routes + AppNavHost con rutas home/collection/history/battle.
- `common/`: badges de rareza, resumen de progreso.
- Paquete por pantalla (menuhome, collection, history, battle) con el trio
  [Estado]ViewModel / [Mapper] (reductor puro) / [Screen].

### Patron MVVM/UDF

Cada ViewModel expone `StateFlow` inmutable de UiState y un `SharedFlow` para
mensajes; los redactores/mappers que transforman dominio a UiState son funciones
puras testeables en JVM. El repositorio/catalogo se inyectan por constructor
via `AppContainer` (ServiceLocator sencillo expuesto por `CardClashApplication`)
para favorecer el testeo.

### Pantallas

- **Home**: menu + resumen de progreso.
- **Collection**: coleccion: nivel/tramo/XP, cartas con rareza/coste/copias
  vs limite por tramo.
- **History**: historial de partidas.
- **Battle**: tablero de combate.

### Logica de sesion de combate (Opcion A)

- Logica pura en `com.cardclash.domain.battle`: `CombatUiState` (modelo UI
  inmutable), `CombatReducer` (mapper snapshot a ui), `MatchSessionController`
  (UDF), e interfaces de puertos `MatchSessionGateway` y `MatchResultSink`.
  Cero android/Firebase en `domain.battle`.
- Adaptadores en la capa de datos: `FirestoreMatchSessionGateway` (implementa
  el gateway envolviendo `FirestoreMatchRepository`, adaptando
  `Task<Void>` a `Result<Unit>` y `ListenerRegistration` a `Closeable`) y
  `LocalMatchResultSink` (persiste el resultado en `PlayerProgressRepository`,
  victoria +5 XP / derrota +2 XP).
- `CombatViewModel` en `com.cardclash.ui.battle` envuelve el controller y expone
  `CombatSessionState`/`CombatUiState`.
- **Modo local demo** (LOCAL_SOLO) por defecto: simula ambos lados con el motor
  + HostSyncEngine local, jugable end-to-end hoy. **Modo en linea**
  (host/cliente) conectado a la interfaz del gateway pero no ejecutable sin
  proyecto Firebase real (`google-services.json` ausente, estrategia WARN); la
  app usa `NoOpMatchSessionGateway` salvo que se inyecte el real.

### MainActivity

Migrado a `ComponentActivity` + `setContent { CardClashApp(container) }`.

## Consecuencias

- UI moderna declarativa con Material 3.
- Estado unidireccional (UDF) testeable en JVM.
- Dominio y capa local puros preservados.
- Firebase confinado a `data/remote/firebase`.
- App lanzable con combate local jugable.
- La cadena Compose + AGP9 + Kotlin embebido exige el plugin
  `kotlin.plugin.compose` con version alineada a la KGP embebida.
- El modo en linea sigue pendiente de un proyecto Firebase real para ser
  ejecutable.
- La composicion visual depende de mappers puros para su testeabilidad.
- Builds verdes verificados con `JAVA_HOME=C:\Program Files\Java\jdk-25.0.2`
  (`clean`, `testDebugUnitTest` y `assembleDebug`).
- 168 unit tests JVM en verde (21 suites, 0 fallos): dominio (motor 20,
  modelo 18, progresion 17, deck 6, rareza 3), battle (reducer 17, controller
  8), datos (sync 7, serializacion 4, HostWritePlanBuilder 5, local 28),
  ui (collections 6, common 6, history 7, home 6, battle 9) + ejemplo.
- Aislamiento de capas verificado: `domain.battle` y `domain/**` puros
  (0 android/Firebase); capa local pura intacta; Firebase confinado a
  `data/remote/firebase`; `android.*` solo en MainActivity,
  CardClashApplication, AppContainer y AppDatabase.
