# ADR-007: Sincronizacion PvP con Firebase Firestore (host autoritativo / cliente)

## Contexto

CardClash incluye modo PvP por turnos entre dos jugadores moviles. Se necesita
un medio para mantener la partida sincronizada entre ambos dispositivos sin que
el juego pueda ser manipulado facilmente y sin depender de un servidor dedicado
gestionado por el equipo.

La solucion debia ser de bajo coste operativo y escalable para partidas 1v1, y
debia permitir que el motor inmutable del dominio (ADR-004) se ejecutara en un
solo punto de autoridad para validar las reglas.

## Opciones consideradas

- **Firebase Firestore con host autoritativo**: un jugador actua como host y
  ejecuta el motor localmente; el otro es cliente. Firestore se usa como canal
  de transporte, no como autoridad. Es la opcion adoptada.
- Firebase RealTime Database: alternativa viable, pero Firestore ofrece mejor
  soporte de reglas de seguridad, consultas y estructura por documentos.
- Servidor dedicado (FastAPI/Spring): maxima seguridad y control, pero coste
  operativo e infraestructura que no se justifican para una 1v1 casual.
- Sincronizacion peer-to-peer directa (WebRTC/sockets): baja latencia, pero gran
  complejidad de NAT, reconciliacion y persistencia.

## Decision

Se adopta la sincronizacion PvP con **Firebase Firestore** siguiendo el patron
de **host autoritativo**. El host ejecuta el motor local, recibe las acciones
del cliente, procesa una a la vez y publica el estado resultante; el cliente
solo envia acciones y recibe proyecciones del estado. Firestore actua como
transporte y medio de persistencia del estado, pero toda la legalidad de las
jugadas la valida el motor en el host, no Firestore.

Los detalles del esquema (snapshot bifurcado `stateHost`/`stateClient`, cola de
acciones, concurrencia y seguridad) se especifican en el ADR-009.

## Consecuencias

- El host es la unica fuente de verdad de las reglas; el cliente no puede
  alterar el resultado de la partida manipulando Firestore.
- Reutilizacion del mismo motor en host y cliente: menor divergencia.
- Dependencia de la disponibilidad de Firestore y de la conexion del host; una
  caida del host compromete la partida.
- Coste de infraestructura bajo y escalabilidad adecuada para partidas 1v1.
- Requiere un diseno de seguridad cuidadoso (ADR-009) para no filtrar la mano
  del rival ni permitir manipulaciones.
